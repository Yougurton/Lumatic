# Редактор окружения в Lumatic: Chroma, Heck и Noodle Extensions

Проект интерфейса и инструментов. Составлен по документации <https://heck.aeroluna.dev/> (все разделы: Getting Started, Tracks and Points, Properties, Additional Events, Environment, User Shared Environments, Notes/Walls, Lighting Events, Settings Setter, Vivify) и сверен с тем, что уже умеет движок просмотра Lumatic.

Статус: предложение, код не менялся.

---

## 1. Что именно даёт документация

Вся работа с окружением в модах сводится к шести вещам. Ниже — что это, чем записывается в карту и какой мод нужен.

| Возможность | Чем записывается | Мод |
|---|---|---|
| Изменить объект игры: скрыть, сдвинуть, повернуть, масштабировать, размножить | `customData.environment[]`: `id` + `lookupMethod`, `active`, `position` / `localPosition`, `rotation` / `localRotation`, `scale`, `duplicate` | Chroma |
| Создать свой объект | `environment[]` с `geometry`: `type` (Sphere, Capsule, Cylinder, Cube, Plane, Quad, Triangle), `material`, `collision` | Chroma |
| Материалы | `customData.materials{}`: `color`, `shader` (Standard, OpaqueLight, TransparentLight, Glowing, BaseWater, BTSPillar, BillieWater, WaterfallMirror, InterscopeConcrete, InterscopeCar), `track`, `shaderKeywords` | Chroma |
| Настроить компоненты объекта | `components`: `ILightWithId` (`lightID`, `type`), `BloomFogEnvironment` (`attenuation`, `offset`, `startY`, `height`), `TubeBloomPrePassLight` (`colorAlphaMultiplier`, `bloomFogIntensityMultiplier`) | Chroma |
| Анимировать | дорожки (`track`) + события `AnimateTrack`, `AnimateComponent`; кривые — `pointDefinitions` (точки, плавности, сплайн, модификаторы, «базы») | Heck + Chroma |
| Связать и подвесить | `AssignTrackParent` (родитель для дорожек), `AssignPlayerToTrack` (игрок: Root, Head, LeftHand, RightHand) | Noodle Extensions |

Дополнительно в документации есть:

- **Общие окружения** — отдельный файл `.dat` в `UserData/Chroma/Environments/` (поля `name`, `author`, `environmentVersion`, `environmentName`, `description`, `features`, `environment`, `materials`).
- **Settings Setter** — рекомендованные настройки игрока в Info.dat (`_settings`).
- **Свойства нот и стен** Noodle (координаты, повороты, размер, фальшивые объекты, анимации пути) — это уже не окружение, но стены часто используют как декорации; см. раздел 9.
- **Vivify** — сцены из Unity (префабы, шейдеры, камеры). Требует сборки asset bundle в Unity, поэтому в Lumatic не редактируется; см. раздел 11.

### Что уже есть в Lumatic

- **Движок просмотра** понимает почти всё перечисленное: поиск объектов всеми пятью способами, `duplicate`, геометрию и все шейдеры, материалы, компоненты, дорожки, `AnimateTrack`, `AssignPathAnimation`, `AssignTrackParent`, `AssignPlayerToTrack`, `AnimateComponent`, сплайны, модификаторы и базы. То есть показывать результат мы уже умеем — не хватает инструментов, чтобы это создавать.
- **Редактор** сейчас умеет только малую часть: готовые окружения из галереи, «убрать детали», размер колец и их света, кольца из геометрии.
- **Запись в карту** уже устроена удобно: всё, что делает Lumatic, пишется одним «фрагментом» (`environment`, `materials`, `customEvents`, `pointDefinitions`), а при следующем сохранении старый фрагмент убирается и пишется новый. Собственные записи карты при этом не трогаются. Новый редактор окружения ложится на этот механизм без переделки.

## 2. Главная идея интерфейса

Пользователь работает со **сценой**, а не с командами и JSON. Он выбирает объект мышью в 3D, двигает его, ставит ключи на таймлайне — а редактор сам пишет `id`, регулярные выражения, дорожки, события и кривые.

Три правила:

1. **Никакого ручного JSON и регулярных выражений.** Всё это редактор составляет сам. Для опытных есть панель «Как это записано», где видно и можно поправить итоговую команду.
2. **Что видишь, то и получишь.** Любое изменение сразу видно в 3D-окне, анимация проигрывается вместе с песней.
3. **Обратимость.** Исходное окружение игры не меняется; у каждого объекта есть «вернуть как было».

### Третья вкладка «Окружение»

Рядом со «Свет» и «Ноты» появляется вкладка **«🏛 Окружение»**. Кнопка «Окружение» на панели (галерея готовых окружений) остаётся — это выбор базового окружения, а вкладка — его редактирование.

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│ Новая · Открыть · Сохранить │ Сложность │ 💡 Свет · ◆ Ноты · 🏛 Окружение │ …      │
├───────────────┬──────────────────────────────────────────────┬───────────────────┤
│ СЦЕНА         │                                              │ ОБЪЕКТ            │
│ 🔍 поиск      │                                              │ Имя, тип          │
│ ▾ Игра        │              3D-окно                         │ ▾ Положение       │
│   ▸ Кольца    │      (выбор, перемещение, поворот,           │ ▾ Материал        │
│   ▸ Лазеры    │       масштаб — рамками в 3D)                │ ▾ Свет            │
│   ▸ Платформа │                                              │ ▾ Дорожка         │
│ ▾ Мои объекты │                                              │ ▾ Анимация        │
│   ◼ Куб 1     │                                              │ ▸ Как записано    │
│   ● Сфера     │  [↔ двигать][⟳ вращать][⤢ масштаб] [⊞ сетка] │                   │
│ ▾ Особые      ├──────────────────────────────────────────────┤                   │
│   ☁ Туман     │ ТАЙМЛАЙН АНИМАЦИИ                            │                   │
│   🧍 Игрок    │ Куб 1 ▸ положение  ◆────◆──────◆             │                   │
│ ▾ Материалы   │        ▸ поворот   ◆───────────◆             │                   │
│   ▣ Зелёный   │ Туман ▸ плотность  ◆──◆                      │                   │
└───────────────┴──────────────────────────────────────────────┴───────────────────┘
```

Четыре области: **сцена** слева, **3D-окно** в центре, **свойства объекта** справа, **таймлайн анимации** снизу. Раскладка та же, что у «Света» и «Нот», переучиваться не нужно.

## 3. Сцена (левая панель)

Дерево всего, что есть в окружении.

**Разделы дерева**

- **Игра** — объекты базового окружения, как они лежат в игре (кольца, лазеры, платформа, здания…). Движок уже знает полную иерархию с настоящими именами, поэтому дерево строится автоматически для любого окружения.
- **Мои объекты** — созданная геометрия и копии.
- **Особые** — «Туман» (один на окружение) и «Игрок» (корень, голова, левая и правая рука).
- **Материалы** — именованные материалы карты.
- **Дорожки** (свёрнуто по умолчанию) — список дорожек и что на них висит.

**Что можно делать в дереве**

- Клик — выбрать (объект подсвечивается в 3D). Ctrl и Shift — несколько.
- 👁 — скрыть объект в игре (`active: false`). Отдельно 🔒 — не давать выбирать в 3D, чтобы не мешал.
- Перетащить объект на другой — сделать его дочерним (см. «Связи», раздел 6).
- Поиск по имени. У объектов игры рядом показывается, сколько таких же («Кольцо ×30»).
- Значки у изменённых объектов: ✎ сдвинут, ◌ скрыт, ⧉ размножен, ▶ анимирован. Фильтр «только изменённые».
- ПКМ: дублировать, скрыть, вернуть как было, выбрать все такие же, выбрать каждый N-й.

**Как выбирать «все такие же».** В игре объекты часто идут рядами: 30 колец, 8 лазеров. Редактор предлагает три варианта области: «только этот», «все такие же», «по правилу» (каждый 2-й, с 5-го по 12-й, чётные). Из выбора он сам строит `id` и `lookupMethod`: один объект — `Exact`, ряд — `Regex` с номерами. Это и есть замена ручных регулярных выражений.

## 4. 3D-окно

Окно то же, что сейчас, плюс инструменты редактирования.

**Выбор и перемещение**

- Клик по объекту — выбрать. Рамка — несколько. Двойной клик — выбрать всю группу (все кольца системы).
- Три рамки-манипулятора, как в любом 3D-редакторе: **двигать (W)**, **вращать (E)**, **масштаб (R)**. Тянуть за ось — по одной оси, за плоскость — по двум.
- Переключатель **«в мире / свои оси»** — он же решает, что пишется в карту: `position` или `localPosition` (документация запрещает оба сразу — редактор этого и не допустит).
- **Привязка**: к сетке (шаг настраивается: 0,1 м, 0,5 м, одна дорожка = 0,6 м), к углам (5°, 15°, 45°), к другим объектам.
- **Камера**: как сейчас (ПКМ + WASD), плюс кнопки «вид игрока», «сверху», «сбоку», «к выбранному» (F).

**Единицы.** В картах v3 положение задаётся в метрах, в v2 — в «дорожках» (1 = 0,6 м). Редактор всегда показывает метры и сам пересчитывает при записи в v2.

**Помощники в окне**

- Силуэт игрока и платформа в натуральную величину — чтобы оценивать размеры.
- Зона, где летят ноты, — полупрозрачный коридор. Объект, попавший в неё, подсвечивается предупреждением: он будет закрывать ноты.
- Линии к родителю у связанных объектов.
- Траектория анимации выбранного объекта — линией, с точками-ключами, которые можно тянуть прямо в 3D.

## 5. Создание объектов и материалы

### Кнопка «＋ Объект»

Семь примитивов из документации: куб, сфера, цилиндр, капсула, плоскость, квадрат, треугольник. Новый объект появляется перед камерой и сразу выбран.

Отдельный пункт **«＋ Свет»** — тот же примитив, но сразу с материалом-лампой (см. ниже).

### Инструменты размножения

Вручную ставить сотню кубов никто не будет, поэтому:

- **Ряд** — N копий с шагом (сдвиг, поворот, масштаб на каждую следующую).
- **По кругу** — N копий вокруг оси, с радиусом и поворотом к центру.
- **Сетка** — N × M × K.
- **Вдоль линии** — нарисовать кривую в 3D, копии встают вдоль неё.
- **Россыпь** — случайно в объёме, с разбросом размера и поворота и «зерном», чтобы результат повторялся.
- **Зеркало** — отразить выбранное слева направо.

Для объектов игры копии пишутся через `duplicate`, для своих — отдельными объектами с общим материалом. После размножения копии остаются **параметрическими**: можно открыть «Ряд» и поменять число или шаг. Кнопка «Сделать отдельными» превращает их в обычные объекты.

### Материалы

Каждому объекту нужен материал, и документация прямо предупреждает: создавать материал на каждый объект — тормоза, нужно переиспользовать. Поэтому:

- В сцене есть раздел **«Материалы»**. Объект ссылается на материал по имени.
- Изменил материал — изменились все объекты с ним.
- При создании объекта подставляется последний использованный материал.
- Кнопка «Сделать своим» создаёт копию материала только для этого объекта.

**Свойства материала**

- **Вид** (шейдер) — плитками с картинкой: обычный, светящийся, лампа непрозрачная, лампа прозрачная, вода, колонна BTS, вода Billie, зеркало-водопад, бетон, машина.
- **Цвет** — тот же выбор цвета, что у света: левый, правый, белый цвет карты или свой.
- **Дорожка цвета** — включается галочкой «Цвет можно анимировать».
- **Ключевые слова шейдера** — в свёрнутом блоке «Дополнительно», списком галочек.

Предупреждение из документации учитываем: с версии игры 1.38 «обычный» шейдер с пустыми ключевыми словами больше не светится — редактор в этом случае сам предложит «Светящийся».

### Свет из геометрии — связь со вкладкой «Свет»

Это главная связка, ради которой всё стоит делать в одном редакторе.

- Материал-лампа (`OpaqueLight`, `TransparentLight`) делает объект источником света, которым управляют обычные события света.
- У такого объекта в свойствах блок **«Свет»**: какая группа света (тип события) и номер лампы (`lightID`).
- Номера редактор **назначает сам**, не пересекаясь с лампами игры и другими объектами. Вручную можно поправить.
- Созданные лампы сразу появляются **строкой на вкладке «Свет»** — как группа, на которую можно ставить события, эффекты и GLS. Название группы берётся из названия объектов.
- Обратно: в строке света кнопка «Показать в окружении» выбирает эти объекты в сцене.

Так пользователь ставит ряд светящихся столбов и тут же рисует по ним волну, не думая о номерах.

## 6. Свойства объекта (правая панель)

Блоки сворачиваются; показываются только те, что применимы к выбранному.

**Положение** — три строки по три барабана: положение, поворот, масштаб. Переключатель «в мире / относительно родителя». Кнопка ↺ у каждой строки — вернуть исходное.

**Копии** (у объектов игры) — число копий; у параметрических рядов — их настройки.

**Материал** (у геометрии) — выбор из списка, «Изменить», «Сделать своим». Галочка **«Осколки отскакивают»** (`collision`).

**Свет** (у ламп) — группа и номер лампы; для трубчатых ламп игры два ползунка: **яркость цвета** (`colorAlphaMultiplier`) и **свечение в тумане** (`bloomFogIntensityMultiplier`).

**Туман** (у объекта «Туман») — четыре ползунка с живым просмотром:

| Ползунок | Поле | Что делает |
|---|---|---|
| Плотность | `attenuation` | насколько густой туман (шкала логарифмическая) |
| Смещение | `offset` | сдвиг начала тумана |
| Нижняя граница | `startY` | с какой высоты начинается перепад |
| Высота перепада | `height` | на какой высоте туман сходит на нет |

Плюс готовые варианты: «чисто», «лёгкая дымка», «густой», «низкий туман».

**Связи**

- **Родитель** — к кому привязан объект. Задаётся перетаскиванием в дереве или пипеткой «выбрать родителя в 3D». Записывается через `AssignTrackParent`.
- Галочка **«Остаться на месте при привязке»** (`worldPositionStays`).
- Привязку можно менять по ходу песни — это событие на таймлайне (раздел 7).
- Для этого нужен Noodle Extensions — редактор предупредит и добавит требование.

**Дорожка** — в обычном режиме скрыта: редактор сам даёт объекту дорожку, когда она понадобилась, с понятным именем (`lm_cube_1`). В «Дополнительно» видно имя, можно переименовать или посадить несколько объектов на одну дорожку.

**Анимация** — список анимаций объекта и кнопка «＋ Анимация» (раздел 7).

**Как это записано** — свёрнутый блок с итоговыми командами JSON для выбранного объекта, только для чтения, с кнопкой «Копировать». Для опытных — режим правки `id` и `lookupMethod` вручную.

## 7. Анимация

Самая большая часть. В модах анимация устроена непривычно: событие `AnimateTrack` с длительностью, а внутри — кривая, где время идёт от 0 до 1. Пользователю это показывать не нужно.

### Ключи вместо событий

Пользователь работает с **ключами на долях песни**, как в любом редакторе анимации:

1. Встал на долю, подвинул объект — появился ключ положения.
2. Встал на другую долю, подвинул ещё — второй ключ. Между ними объект движется сам.

Редактор сам режет это на события `AnimateTrack`, пересчитывает доли в доли-от-длительности и складывает одинаковые кривые в `pointDefinitions`, чтобы файл не раздувался.

Режим **«Автоключ»** (кнопка ⏺): пока он включён, любое изменение в 3D ставит ключ на текущей доле. Выключен — меняется исходное положение объекта.

### Таймлайн анимации

Тот же таймлайн, что у света, но со строками объектов:

```
▾ Куб 1
    положение    ◆━━━━━━◆━━━━━━━━━━◆
    поворот      ◆━━━━━━━━━━━━━━━━━◆ ↻×4
    масштаб      ◆━━◆
▾ Материал «Зелёный»
    цвет         ◆━━━━━━◆━━━━◆
▾ Туман
    плотность    ◆━━━━━━━━◆
▾ Игрок
    положение    ◆━━━━━━━━━━━━━━━━━◆
```

- Ключи — ромбы, их можно тянуть, копировать, растягивать группой.
- Полоса между ключами — переход; клик по ней открывает выбор плавности (тот же выбор, что у переходов света).
- Значок ↻×N — повтор (`repeat`).
- Спектрограмма и сетка — общие с остальным редактором.
- Работают все привычные клавиши: копировать, вставить, дублировать, зеркалить во времени.

### Что можно анимировать

| Чей | Свойство | Поле |
|---|---|---|
| Объект | положение, поворот, масштаб (в мире или свои) | `position`, `localPosition`, `rotation`, `localRotation`, `scale` |
| Материал | цвет | `color` |
| Лампа игры | яркость цвета, свечение в тумане | `AnimateComponent` → `TubeBloomPrePassLight` |
| Туман | плотность, смещение, нижняя граница, высота | `AnimateComponent` → `BloomFogEnvironment` |
| Игрок и его части | положение, поворот | `AssignPlayerToTrack` + `AnimateTrack` |

### Редактор кривой

Двойной клик по переходу открывает кривую:

- График значения от времени, точки тянутся мышью.
- У каждой точки — плавность (все с easings.net, плюс линейная и ступенькой).
- Для положения и поворота — галочка **«Плавная кривая через точки»** (`splineCatmullRom`).
- Предупреждение из документации показываем прямо здесь: поворот считается кватернионами, поэтому «0° → 360°» — это отсутствие движения. Для полного оборота редактор сам ставит промежуточные точки (0, 90, 180, 270, 360).

### Готовые движения

Чтобы не ставить ключи руками на типовые вещи — кнопка **«＋ Движение»**, как эффекты у света:

- **Вращение** — вокруг оси, оборотов за N долей.
- **Покачивание** — туда-обратно по оси.
- **Пульс** — масштаб в такт.
- **Орбита** — по кругу вокруг точки или объекта.
- **Тряска** — случайные рывки.
- **По траектории** — вдоль нарисованной линии.
- **Появление и исчезновение** — вылет из-за горизонта, рост из нуля.
- **По звуку** — масштаб или яркость по громкости песни (тот же анализ, что у эффектов света «по звуку»).

Движение — это блок на таймлайне с настройками справа. Его можно растянуть, скопировать, а при необходимости «разобрать на ключи».

Так как на одном объекте может быть несколько дорожек, движения **складываются**: объект может одновременно лететь по орбите и вращаться вокруг себя. В интерфейсе это просто две строки у одного объекта.

### Следить за игроком и цвета карты («базы»)

В документации это значения, которые игра подставляет на лету: положение головы и рук, цвета нот, сабель и света, комбо, счёт, энергия, время песни. В редакторе это оформлено без формул:

- У положения и поворота — галочка **«Следовать за…»**: голова, левая рука, правая рука, с ползунком **плавности** (в модах это `.s10`). Типичное применение — надпись или рамка, которая плавно едет за взглядом.
- У цвета в выборе цвета — пункты **«Как у игрока»**: цвет левой или правой ноты, сабли, стен, света. Объект красится под цветовую схему игрока.
- Блок **«Зависит от…»**: комбо, энергия, процент счёта, время песни — с простым правилом «значение × множитель + сдвиг». Например, столб растёт вместе с энергией.

Для опытных — поле **«Выражение»**, где видны и правятся модификаторы (`opAdd`, `opMul`…) и выбор компонент (`baseHeadPosition.zy`).

### Игрок

Объект «Игрок» в дереве. Его можно двигать и вращать ключами, как любой другой, — платформа с игроком поедет по сцене.

Документация предупреждает жёстко: неравномерное движение и любые повороты игрока вызывают укачивание. Поэтому:

- При первой анимации игрока — предупреждение с объяснением.
- По умолчанию плавность у игрока только линейная, поворот выключен; включается отдельной галочкой «Я понимаю риск».
- Проверка карты (вкладка «Ошибки») получает правила: резкий разгон, поворот игрока, слишком большая скорость.

## 8. Проверки, подсказки, нагрузка

**Проверка окружения** — новая группа правил во вкладке «Ошибки»:

- дорожка анимируется, но на ней ничего нет (в игре это ошибка);
- заданы сразу и положение в мире, и своё;
- объект закрывает зону нот;
- у кривой неверное число значений в точке;
- слишком много материалов (нужно переиспользовать);
- лампы с одинаковым номером в одной группе;
- анимация игрока с поворотом или рывком.

**Счётчик нагрузки** внизу сцены: объектов, материалов, ламп, событий анимации — с цветом «нормально / много / тяжело для Quest». Пороги подберём на практике.

**Требования к модам** редактор ставит сам:

- изменения окружения и геометрия — Chroma (требование);
- привязки и анимация игрока — ещё и Noodle Extensions;
- при удалении последнего такого объекта требование снимается (этот механизм уже есть).

**Проверка в игре.** В документации описан ReLoader: перезагрузка карты без выхода из песни. В окне «Отправить на Quest» и в справке дадим короткую инструкцию: как включить, какие клавиши, и что изменения окружения применяются только после перезапуска песни (`ReloadOnRestart`).

## 9. Ноты и стены: свойства Noodle

Это не окружение, но в документации идёт рядом, и стены массово используют как декорации. Часть уже сделана (свободная сетка: `coordinates`, `size`). Остальное — на вкладке «Ноты», в панели «Выделено», блок **«Noodle»**:

| Свойство | Поле | Для чего |
|---|---|---|
| Поворот в мире | `worldRotation` | откуда летит объект (как режим 360°) |
| Свой поворот | `localRotation` | наклон самой ноты или стены |
| Масштаб | `scale` | размер (меняет и зону удара) |
| Скорость и отступ | `noteJumpMovementSpeed`, `noteJumpStartBeatOffset` | своя скорость подлёта у объекта |
| Нельзя задеть | `uninteractable` | декоративный объект |
| Ненастоящий | массивы `fakeColorNotes`, `fakeBombNotes`, `fakeObstacles`, `fakeBurstSliders` | не идёт в счёт |
| Переворот | `flip` | вылет ноты сбоку |
| Без подъёма, без поворота к игроку | `disableNoteGravity`, `disableNoteLook` | |
| Не засчитывать ошибки | `disableBadCutDirection`, `disableBadCutSpeed`, `disableBadCutSaberType` | |
| Связать | `link` | ноты режутся вместе |
| Цвет, эффект появления, осколки | `color`, `spawnEffect`, `disableDebris` (Chroma) | |

**Анимация нот и стен**

- Свойства: смещение, поворот, масштаб, растворение, растворение стрелки, «можно задеть», точная траектория (`definitePosition`), ход времени (`time`), цвет.
- Два вида: «для всех на дорожке одновременно» (`AnimateTrack`) и «путь каждого объекта за его жизнь» (`AssignPathAnimation` или `animation` у самого объекта).
- Интерфейс — тот же редактор кривой, но шкала времени подписана понятно: «появился → долетел до игрока (0,5) → улетает (0,75) → исчез (1)».
- Готовые пути: «падает сверху», «вылетает сбоку», «по спирали», «проявляется».

**Стены-декорации** — отдельный инструмент: рисуешь примитив в 3D-редакторе окружения и выбираешь «Сделать стенами». Получаются ненастоящие, незадеваемые стены нужного размера и поворота. Это способ получить геометрию, которая живёт по времени нот, а не весь трек.

Этот раздел — отдельный большой этап после окружения.

## 10. Общие окружения и рекомендованные настройки

**Экспорт окружения в файл.** Кнопка «Сохранить как окружение Chroma» собирает файл `.dat` для папки `UserData/Chroma/Environments/`:

- название, автор, версия, описание, базовое окружение — форма с полями;
- **возможности** (`features`): «включить цвета и номера ламп Chroma», «фильтр эффектов» (все, без стробов, без эффектов), «вшить события света»;
- окружение и материалы берутся из сцены.

Анимации в такой файл не попадают — формат их не предусматривает; редактор предупредит.

**Импорт**

- из файла `.dat` общего окружения;
- из другой карты (выбрать папку и сложность);
- из уже открытой карты: её собственные записи окружения превращаются в объекты сцены, которые можно править. Сейчас Lumatic такие записи только показывает.

**Своя галерея.** Сцену можно сохранить в галерею готовых окружений Lumatic (рядом с ChaseEnvs, BSCEL и другими) и применять к другим картам.

**Рекомендованные настройки (Settings Setter).** В «Свойствах карты» новый раздел по сложностям — список галочек и ползунков по категориям из документации: игрок, модификаторы, окружение, цвета, графика, Chroma. Документация просит указывать только действительно нужное, поэтому по умолчанию всё пусто, а сверху короткое пояснение. Полезные для нас случаи предложим кнопками: «выключить левшу» (если в окружении есть текст), «включить зеркала», «не подменять окружение и цвета».

## 11. Что не входит

**Vivify.** Префабы, свои шейдеры, камеры и постобработка требуют проекта в Unity определённой версии и сборки asset bundle. Сделать это внутри Lumatic нельзя. Разумный минимум:

- не ломать такие карты: события и ссылки на бандлы сохраняются как есть;
- показывать на таймлайне события Vivify строкой «только чтение».

Редактирование Vivify — отдельный разговор, если понадобится.

**Точность просмотра.** Шейдеры воды, зеркал и некоторых материалов в нашем движке — приближение, а не копия игровых. Финальный вид нужно проверять в игре; редактор это честно пишет рядом с такими материалами.

## 12. Как это устроено внутри

Коротко, чтобы было понятно, на что это опирается.

- **Сцена хранится в проекте Lumatic** (`*.lumatic.json`), а не в карте: объекты, материалы, параметрические ряды, ключи, движения. В карту пишется только результат.
- **Компилятор** превращает сцену во фрагмент: `environment`, `materials`, `customEvents`, `pointDefinitions`. Он же назначает имена дорожек и номера ламп, объединяет одинаковые кривые, переводит единицы для v2.
- **Запись** идёт через существующий механизм фрагментов: старое убирается, новое вставляется, чужие записи карты не трогаются.
- **Просмотр** — существующий движок; ему добавляются выбор объектов лучом, рамки-манипуляторы и рисование траекторий.
- **Карты v2 и v3.** Документация описывает формат v3. В v2 поля называются иначе, единицы другие, и Lumatic сейчас пишет в v2 только простые записи окружения (без геометрии и анимаций). Что именно из остального работает в v2, нужно проверить отдельно. Редактор покажет, что не запишется, и предложит перевести сложность в v3 — конвертер уже есть.

## 13. Порядок работ

Каждый этап — законченная полезная версия.

| Этап | Что появляется | Примерный объём |
|---|---|---|
| 1 | Вкладка «Окружение»: дерево сцены, выбор в 3D, рамки «двигать / вращать / масштаб», скрыть, копии, «вернуть как было». Импорт существующих записей карты в сцену | большой |
| 2 | Создание геометрии, материалы, лампы из геометрии со строками на вкладке «Свет» | большой |
| 3 | Инструменты размножения: ряд, круг, сетка, вдоль линии, россыпь, зеркало | средний |
| 4 | Таймлайн анимации: ключи, автоключ, переходы, редактор кривой, повтор; анимация объектов и цвета материалов | очень большой |
| 5 | Связи (родитель), туман и свойства ламп с анимацией, игрок с защитой от укачивания | средний |
| 6 | Готовые движения, «следовать за игроком», цвета игрока, «зависит от…» | средний |
| 7 | Проверки окружения, счётчик нагрузки, экспорт и импорт `.dat`, своя галерея, рекомендованные настройки | средний |
| 8 | Ноты и стены: свойства Noodle, анимации пути, стены-декорации | очень большой |

Этапы 1–2 дают то, чего сейчас нет вообще: собрать своё окружение мышью. Этап 4 — самый рискованный по объёму, его стоит начинать с простого случая (положение одного объекта) и расширять.

## 14. Принятые решения

1. **Отдельная вкладка.** На панели она называется «🏛 Сцена»: кнопка «Окружение» там уже есть (галерея готовых окружений), два одинаковых названия путали бы.
2. **Порядок:** сначала статическая сцена (этапы 1–3), потом анимация.
3. **Ноты и стены Noodle** — в самом конце (этап 8).
4. **Карты v2:** редактор сцены рассчитан на v3; для v2 предлагаем перевод в v3. Того, что есть в v2 и пропало в v3, редактору не нужно (устаревший градиент света, «пропы» колец, несколько параметров событий колец, отдельное событие тумана).
5. **Режим для опытных нужен** — чтобы мапперы, которые умеют работать с Chroma и Noodle, могли дать обратную связь. Первый шаг уже есть: блок «Как это записано в карту».

## 15. Что уже сделано

**Этап 1, первая часть (версия 0.26.0)**

- Вкладка «🏛 Сцена»: слева дерево объектов окружения игры (поиск, «только изменённые», глаз — скрыть), справа свойства выбранного.
- Выбор объекта кликом в 3D (повторный клик в ту же точку — следующий объект за ним; Ctrl — добавить) и в дереве.
- Рамка вокруг выбранного и ручки в 3D: двигать (W), вращать (E), масштаб (R).
- Положение, поворот и масштаб барабанами; «вернуть как в игре» по каждой строке и целиком.
- Изменения видны в 3D, отменяются (Ctrl+Z) и пишутся в карту командами Chroma (`id` + `Exact`, `localPosition`, `localRotation`, `scale`, `active`); требование Chroma ставится само.

**Этап 1, вторая часть и начало этапа 2 (версия 0.27.0)**

- Выбор в дереве как в Проводнике: Ctrl — по одному, Shift — всё от прошлого до этого. Стрелка раскрытия у выбранного раскрывает все выбранные.
- Несколько выбранных меняются вместе: барабаны и ручки в 3D сдвигают, поворачивают и масштабируют все на одну величину.
- Ручки «✥ Всё» (Q): стрелки и кольца поворота сразу; привязка (0,1 м, 15°, 0,1 размера).
- Копия объекта игры (`duplicate`, Ctrl+D) и своих объектов; «все такие же», «каждый второй»; меню по правой кнопке в дереве.
- «⤓ Взять записи карты»: простые собственные записи окружения (точный `id`; фигуры) становятся объектами сцены.
- Свои объекты: фигуры (`geometry`), материалы (вид, цвет), лампы — с номером (light ID), типом события и кнопкой «Сделать группой света» (строка на вкладке «Свет»).

**Хвосты этапов 1–2 и этап 3 (версия 0.28.0)**

- Общий режим ручек «Всё» убран: остались три отдельных — двигать (W), вращать (E), масштаб (R).
- Выбор по правилу: из таких же — каждый N-й, с какого и по какой. Привязка: фигура встаёт вровень с соседней.
- Материалы: вид плитками; в «Дополнительно» — дорожка для анимации цвета и ключевые слова шейдера (текстом: списка слов в документации нет).
- В меню строки группы света — «Показать в окружении» (выбирает её лампы в сцене).
- Размножение: ряд, по кругу, сетка, вдоль линии (отрезок с изгибом, задаётся числами), россыпь; зеркальная копия. Копии остаются параметрическими, «Сделать отдельными» превращает их в обычные объекты. У объекта игры первым в ряду остаётся он сам, копии пишутся через `duplicate`. Лампы в копиях получают свои номера и входят в группу света.

**Этап 4, первая часть (версия 0.29.0)**

- Ключи положения, поворота и масштаба на долях песни — у своих объектов и у объектов игры. До первого ключа объект стоит как задан без анимации, после последнего — остаётся как в нём.
- Пока открыта «Сцена», на таймлайне вместо строк света — строки анимации: ромбы-ключи, полосы переходов. Клик — выбрать ключ и перейти к нему, тянуть — сдвинуть, рамка — выбрать несколько, двойной клик — новый ключ, ПКМ — плавность, Delete — удалить.
- «⏺ Автоключ»: любое изменение ручками или барабанами ставит ключ на текущей доле. Без него меняется исходное положение, а у уже анимированного свойства — ключ. Клавиша K — ключ того, что меняют ручки.
- Рамка и ручки в 3D стоят там, где объект находится на текущей доле; числа в свойствах — тоже.
- В карту пишется дорожка на объекте и по одному `AnimateTrack` на свойство.

**Осталось в этапе 4:** редактор кривой, плавная кривая через точки, повтор (`repeat`), копирование и вставка ключей, анимация цвета материалов, автоматическая разбивка полного оборота, траектория в 3D, анимация копий внутри размножения (сейчас анимируется только сам объект).

**Не сделано из задуманного в этапах 1–3:** привязка к объектам игры (только к своим фигурам), линия, нарисованная мышью в 3D, переключатель «в мире / свои оси», замок 🔒 в дереве.
